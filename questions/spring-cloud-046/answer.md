1. **定义**：微服务网关是系统的统一入口，所有外部请求先到达网关，网关负责路由转发、鉴权认证、限流熔断、日志监控、协议转换等，然后把请求转发到对应的后端微服务。

2. **为什么需要**：
   - **统一入口**：客户端不需要知道后端有多少个服务、每个服务的地址是什么，只需要访问网关就行。
   - **安全屏障**：网关做统一的鉴权认证（JWT/OAuth2），后端服务不需要重复实现。
   - **流量管控**：网关做统一的限流、熔断、灰度路由。
   - **协议转换**：外部用 HTTP，内部可能用 RPC/Dubbo，网关做协议转换。
   - **日志监控**：网关统一记录请求日志、调用耗时，方便排查问题。
   - **减少客户端复杂度**：客户端不需要跟多个服务交互，只需要跟网关一个入口打交道。

3. **网关的位置**：网关在微服务架构的最外层，客户端（Web/App/第三方）→ 网关 → 微服务集群。

4. **典型功能**：路由转发、负载均衡、鉴权认证、限流熔断、日志监控、协议转换、跨域处理、请求/响应改写、灰度发布。

## 扩展知识

- **网关的性能**：网关是所有请求的入口，性能至关重要。Spring Cloud Gateway 基于 WebFlux（Netty + Reactor），异步非阻塞，性能比 Zuul 1.x（基于 Servlet，同步阻塞）高很多。
- **网关的高可用**：网关必须做集群部署（至少2个节点），前面挂负载均衡（Nginx/SLB）。网关本身无状态，可以水平扩展。
- **网关 vs 服务网格**：网关处理南北流量（外部到内部），服务网格处理东西流量（内部服务之间）。两者不冲突，可以同时使用。
