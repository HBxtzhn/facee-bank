- **实现复杂度**：跳表实现简单（约 100 行核心代码），只需处理指针的前后插入/删除。红黑树实现复杂（约 500+ 行），涉及旋转、变色、平衡维护等。
- **范围查询**：跳表天然支持高效的范围查询。找到起点后沿最底层链表顺序遍历即可，O(log N + M)。红黑树范围查询需中序遍历，实现复杂且缓存不友好。
- **并发性能**：跳表的局部修改（插入/删除）只影响相邻节点，不影响全局结构。红黑树的旋转操作可能影响较大范围的节点，并发控制更复杂。
- **可调性**：跳表通过调整层数概率（p 值）控制空间/时间权衡。p=0.25 省内存但层数少，p=0.5 层数多但查找更快。红黑树没有这种灵活性。
- **内存局部性**：跳表底层节点连续遍历，缓存命中率高。红黑树节点分散，遍历时缓存命中率低。

## 扩展知识

**Redis 作者 antirez 的解释**：
1. 跳表实现简单，代码可读性高
2. 跳表的范围查询比红黑树更自然、更高效
3. 跳表可以通过调整参数适配不同场景
4. 跳表在内存中更稀疏，插入/删除不需要重建平衡

**性能对比（理论分析）**：
- 查找：跳表 O(log N)，红黑树 O(log N)，相当
- 插入：跳表 O(log N)（需更新各层指针），红黑树 O(log N)（需旋转平衡），相当
- 删除：跳表 O(log N)，红黑树 O(log N)，相当
- 范围查询：跳表 O(log N + M)（顺序遍历），红黑树 O(log N + M)（中序遍历），但跳表实现更简单
- 内存：跳表每节点需存储多层指针（平均 1.33 层），红黑树每节点需 2 个子指针 + 1 父指针 + 1 颜色位，相当

**其他使用跳表的系统**：
- LevelDB / RocksDB：MemTable 用跳表实现并发安全版本
- Lucene：索引结构中使用跳表
- C++ STL：`std::skip_list`（部分实现）

## 对比表格

| 特性 | 跳表（Skip List） | 红黑树（Red-Black Tree） |
|------|------------------|------------------------|
| 实现复杂度 | 低（~100 行） | 高（~500+ 行） |
| 平衡维护 | 随机层数，无需旋转 | 旋转 + 变色 |

| 缓存局部性 | 好（底层连续） | 差（节点分散） |
| 参数可调 | 是（p 值） | 否 |
| 最坏情况 | O(N)（概率极低） | O(log N)（保证） |
| 代码可读性 | 高 | 低 |
