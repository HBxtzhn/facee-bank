## 追问 1：AT 模式的 before image 和 after image 是怎么生成的？

执行 SQL 前，Seata 的 SQL 解析器解析出表名和 WHERE 条件，根据这些信息生成 SELECT 语句查询出要修改的数据（before image）。执行完业务 SQL 后，根据主键再查一次得到修改后的数据（after image）。两个 image 序列化成 JSON 写入 undo_log 表。

## 追问 2：如果二阶段回滚时发现数据已经被其他事务修改了怎么办？

Seata 会做数据校验——把 undo_log 里的 after image 和当前数据库的数据做对比。如果一致，说明没有被其他事务修改，可以安全回滚。如果不一致，说明有脏数据，Seata 不会自动回滚，而是记录日志并告警，需要人工介入处理。这就是 AT 模式的最终一致性保证。

## 追问 3：Seata 的全局锁和数据库的本地锁有什么区别？

数据库本地锁（行锁、表锁）是数据库层面的，保证单个数据库内的并发安全。Seata 全局锁是应用层面的，保证跨数据库的并发安全。一阶段本地事务提交前，先拿到数据库本地锁执行 SQL，再向 TC 申请全局锁。两个锁都拿到了才能提交。全局锁在二阶段提交后释放。
