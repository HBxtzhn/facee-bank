- **全量复制**：从节点首次连接主节点时，主节点执行 `BGSAVE` 生成 RDB 快照，将快照发送给从节点，从节点加载到内存；期间主节点继续处理写命令，产生的写命令缓存在 repl_backlog 中，快照发送完毕后再将缓冲区中的增量命令发送给从节点执行。
- **增量复制**：全量复制完成后，主节点每执行一条写命令都会异步传播给所有从节点（基于 offset 机制），实现数据实时同步。
- **断线重传**：从节点与主节点断开后重连，若 repl_backlog 中对应 offset 的数据仍在，则执行增量复制；否则退化为全量复制。
- **心跳机制**：主从节点之间每秒发送一次 `PING`/`REPLCONF ACK` 心跳，用于检测连接状态和确认复制进度。

## 扩展知识

- **repl_backlog**：主节点维护一个固定大小（默认 1MB）的环形缓冲区，记录最近传播的写命令。通过 `master_repl_offset` 和 `repl_backlog_size` 控制。从节点携带自身的 `slave_repl_offset` 请求重连，主节点据此判断能否增量复制。
- **复制偏移量（offset）**：主从各自维护一个复制偏移量，通过比对两者差异即可知道数据是否一致。
- **无磁盘复制（diskless replication）**：Redis 4.0+ 支持 `repl-diskless-sync yes`，主节点直接将 RDB 通过 socket 发送给从节点，不落盘，适用于磁盘 I/O 瓶颈场景。
- **PSYNC 命令**：Redis 2.8+ 使用 `PSYNC` 替代旧版 `SYNC`，同时支持全量（`PSYNC ? -1`）和增量（`PSYNC runid offset`）两种模式。

## 对比表格

| 特性 | 全量复制 | 增量复制 |
|------|---------|---------|
| 触发时机 | 首次连接 / 断线后 backlog 数据丢失 | 正常同步 / 短暂断线后重连 |
| 数据量 | 整个数据集的 RDB 快照 | 仅断线期间的增量命令 |
| 性能开销 | 高（fork 子进程 + 网络传输） | 低（仅传输增量命令） |
| 核心命令 | BGSAVE + PSYNC | PSYNC + repl_backlog |
