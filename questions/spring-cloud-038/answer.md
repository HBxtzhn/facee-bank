1. **定义**：服务降级是指当服务不可用或响应过慢时，不继续等待或报错，而是返回一个兜底数据（默认值、缓存值、友好提示），保证核心流程能继续运行。

2. **降级策略**：
   - **返回默认值**：比如推荐服务挂了，返回默认的推荐列表。
   - **返回缓存值**：比如商品详情接口超时，返回 Redis 缓存的旧数据。
   - **返回友好提示**：比如"系统繁忙，请稍后重试"。
   - **主动关闭非核心功能**：比如大促期间关闭评论功能、推荐功能，保证核心交易流程。

3. **降级触发条件**：
   - 熔断器触发（失败率超过阈值）
   - 调用超时
   - 线程池/信号量满了
   - 手动降级（运维人员主动触发）

4. **降级 vs 熔断**：熔断是自动触发的保护机制（检测到故障自动断开），降级是熔断后的处理策略（返回兜底数据）。熔断是"因"，降级是"果"。也可以不熔断直接降级（比如主动降级非核心功能）。

## 扩展知识

- **Sentinel 降级配置**：通过 @SentinelResource(fallback = "orderFallback") 注解指定降级方法。降级方法必须跟原方法参数一致，返回值一致。也可以通过 lockHandler 指定限流/熔断时的处理方法。
- **Feign + Sentinel 降级**：Feign 集成 Sentinel 后，可以在 @FeignClient(fallback = OrderClientFallback.class) 指定降级实现类。降级类实现 Feign 接口，返回兜底数据。
- **降级要谨慎**：降级数据可能跟真实数据不一致（比如缓存的旧数据），要评估业务影响。核心链路（比如支付、下单）一般不降级，而是熔断后直接报错。
