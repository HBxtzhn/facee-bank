## 追问 1：你的项目里哪些场景做了降级？

非核心功能做了降级——推荐服务挂了返回默认推荐列表，评论服务挂了不显示评论区，消息通知服务挂了异步重试。核心功能（下单、支付）不做降级，熔断后直接报错，让用户重试。降级策略要根据业务重要性来定，核心链路不能降级。

## 追问 2：降级和缓存有什么关系？

缓存可以作为降级的数据源。比如服务正常时，每次请求的结果写入 Redis 缓存；服务挂了触发降级，从 Redis 读取缓存数据返回。这样用户看到的是旧数据，但不至于看到错误页面。这就是"缓存 + 降级"的组合策略。

## 追问 3：怎么实现主动降级？

通过配置中心（Nacos）下发降级开关，服务监听到开关变更后，直接返回降级数据，不实际调用下游服务。比如大促期间，运营在 Nacos 里把推荐功能的开关关掉，推荐接口直接返回默认列表，不再调用推荐服务。这样可以释放资源给核心功能。
