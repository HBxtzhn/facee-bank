1. **定义**：令牌桶算法（Token Bucket）是一种限流算法。以固定速率往桶里放令牌（Token），请求需要拿到令牌才能被处理。桶有容量上限，满了之后多余的令牌被丢弃。如果桶里没有令牌，请求被拒绝。

2. **工作原理**：
   - 桶的容量为 N（最大令牌数）。
   - 以固定速率 R（每秒 R 个令牌）往桶里放令牌。
   - 请求到来时，从桶里取一个令牌。取到了就处理请求，取不到就拒绝。
   - 桶满了之后，新放的令牌被丢弃（不累积）。

3. **核心特点**：
   - **允许突发流量**：桶里有囤积的令牌时，可以瞬间处理大量请求（比如桶容量100，攒满了可以瞬间处理100个请求）。
   - **限制平均速率**：长期来看，处理速率不会超过令牌的生成速率 R。
   - **灵活性**：可以调整桶容量（控制突发量）和生成速率（控制平均速率）。

4. **使用场景**：
   - **API 限流**：限制某个 API 的调用频率（比如每秒100次）。
   - **接口保护**：保护下游服务不被突发流量压垮。
   - **用户限流**：限制单个用户的请求频率（防止恶意刷接口）。
   - **消息消费**：控制消息消费的速率，防止消费过快压垮下游。

## 扩展知识

- **实现方式**：
   - **Guava RateLimiter**：Java 里最常用的令牌桶实现。RateLimiter.create(10.0) 创建一个每秒生成10个令牌的限流器。
ateLimiter.tryAcquire() 尝试获取令牌，获取不到就拒绝。
   - **Redis + Lua**：分布式令牌桶，用 Redis 存储令牌数，Lua 脚本保证原子性。适合集群限流。
   - **Sentinel**：Sentinel 的匀速排队模式基于漏桶算法，但 QPS 限流模式本质上是滑动窗口计数器。

5. **代码示例**：

``java
// Guava RateLimiter 示例
RateLimiter rateLimiter = RateLimiter.create(10.0); // 每秒10个令牌

public void handleRequest() {
    if (rateLimiter.tryAcquire()) {
        // 获取到令牌，处理请求
        processRequest();
    } else {
        // 没有令牌，拒绝请求
        rejectRequest();
    }
}
``

## 概念对比

| 特性 | 令牌桶 | 漏桶 |
|------|--------|------|
| 处理速率 | 允许突发（桶里有令牌时） | 固定速率 |
| 桶的作用 | 存储令牌 | 存储请求 |
| 溢出处理 | 令牌满了丢弃令牌 | 请求满了丢弃请求或排队 |
| 适用场景 | 允许突发，限制平均速率 | 需要匀速处理 |
