- **惰性删除（Lazy Expiration）**：客户端访问 key 时，Redis 检查该 key 是否过期，若过期则删除并返回 nil。优点：CPU 友好；缺点：过期 key 可能长期占用内存。
- **定期删除（Active Expiration）**：Redis 每 100ms 随机抽取一批设置了过期时间的 key（默认 256 个），检查并删除已过期的 key。若过期比例 > 25%，则继续抽取，直到过期比例 ≤ 25% 或扫描时间超过 25ms。
- **两者结合**：Redis 同时使用惰性删除和定期删除，互补不足。

## 扩展知识

- **定期删除的算法细节**：
  - 使用快速测试（fast test）：若上次扫描耗时未超过时限的 2 倍，则跳过本轮。
  - 每轮最多扫描 `databases` × 16 个数据库（可配置）。
  - 扫描时间上限为 25ms（`ACTIVE_EXPIRATION_CYCLE`），避免长时间阻塞。
- **过期字典（expires dict）**：Redis 用单独的字典存储所有 key 的过期时间（值为毫秒级时间戳），定期删除时只扫描此字典，而非遍历所有 key。
- **主从节点的过期处理**：主节点过期删除后，通过 DEL 命令传播给从节点；从节点不主动删除过期 key，而是等待主节点的 DEL 命令，保证主从一致性。

## 对比表格

| 策略 | 触发时机 | 优点 | 缺点 |
|------|---------|------|------|
| 惰性删除 | 访问 key 时 | 不浪费 CPU | 过期 key 可能长期占内存 |
| 定期删除 | 每 100ms 执行 | 及时释放内存 | 消耗 CPU，可能遗漏 |
| 两者结合 | 访问时 + 定时 | 平衡 CPU 和内存 | 实现稍复杂 |
