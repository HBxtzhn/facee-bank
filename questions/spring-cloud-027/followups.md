## 追问 1：你的项目里用的什么负载均衡？

对外用阿里云 SLB 做入口负载均衡，Nginx 做七层路由和反向代理，内部微服务之间用 Spring Cloud LoadBalancer 做客户端负载均衡。注册中心（Nacos）维护服务列表，LoadBalancer 从 Nacos 拿到列表后按轮询算法选实例。

## 追问 2：Nginx 和 LVS 怎么选？

LVS 性能更高（内核态转发），但只支持四层，配置复杂。Nginx 功能更丰富（七层路由、rewrite、限流等），配置简单。一般大型项目用 LVS + Nginx 的组合：LVS 在前面做四层分发（抗住大流量），Nginx 在后面做七层路由（处理业务逻辑）。中小项目直接用 Nginx 就够了。

## 追问 3：客户端负载均衡的缺点是什么？

第一，每个客户端都要维护服务列表，占用内存；第二，负载均衡逻辑分散在每个客户端里，升级算法要改所有服务；第三，不能做全局的流量控制（比如按比例分配流量到不同机房）。但对于微服务场景，客户端负载均衡减少了网络跳转，性能更好，是更合适的选择。
