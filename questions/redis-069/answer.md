- **数据分片**：Cluster 支持数据分片（16384 个 hash slot 分布到多个主节点），每个节点只存储部分数据。Sentinel 不分区，每个实例存储全量数据。
- **高可用方式**：Cluster 通过主从节点自动故障转移实现高可用。Sentinel 通过哨兵进程监控主从实例，主节点故障时选举新主节点。
- **扩容能力**：Cluster 支持在线水平扩容（增加节点 + 迁移 slot）。Sentinel 只能垂直扩容（增加从节点做读扩展）。
- **架构复杂度**：Cluster 去中心化（gossip 协议通信），客户端可连接任意节点。Sentinel 中心化（哨兵集群做决策），客户端通常连接 Sentinel 获取主节点地址。
- **适用场景**：Cluster 适合大数据量、高并发场景。Sentinel 适合数据量不大但需要高可用的场景。

## 扩展知识

**Redis Cluster 的核心机制**：
- **Hash Slot**：`CRC16(key) % 16384` 决定 key 属于哪个 slot
- **Gossip 协议**：节点间通过 PING/PONG/MEET/FAIL 消息交换状态信息
- **故障判定**：多数主节点认为某节点不可达 → 标记为 FAIL → 触发故障转移
- **MOVED/ASK 重定向**：客户端访问错误节点时，返回 MOVED（永久迁移）或 ASK（迁移中）引导客户端到正确节点

**Sentinel 的核心机制**：
- **主观下线（SDOWN）**：单个 Sentinel 认为实例不可达
- **客观下线（ODOWN）**：quorum 个 Sentinel 都认为主节点不可达
- **Leader 选举**：Raft 算法选出 Leader Sentinel 执行故障转移
- **通知与重配置**：通知客户端新主节点地址，将从节点升级为新的主节点

## 对比表格

| 特性 | Redis Cluster | Redis Sentinel |
|------|--------------|----------------|
| 数据分布 | 分片存储（16384 slot） | 全量存储（每节点完整副本） |
| 水平扩展 | 支持（加节点 + 迁移 slot） | 不支持（只能加从节点） |
| 高可用机制 | 节点间 gossip + 自动故障转移 | 哨兵监控 + 选举故障转移 |
| 去中心化 | 是（gossip 协议） | 否（哨兵集群中心化决策） |
| 客户端感知 | 客户端需处理 MOVED/ASK | 客户端连接 Sentinel 获取地址 |
| 最小节点数 | 3 主 + 3 从 = 6 节点 | 1 主 + 1 从 + 3 哨兵 = 5 进程 |
| 运维复杂度 | 较高（slot 管理、数据迁移） | 较低（自动故障转移） |
| 数据容量上限 | 所有主节点内存之和 | 单个主节点内存上限 |
| 跨 slot 操作 | 需用 hash tag 保证同 slot | 无限制（单节点全量数据） |
