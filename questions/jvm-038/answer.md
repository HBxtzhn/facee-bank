**AOT（Ahead-Of-Time Compiler，提前编译器）**是在程序运行之前，就把字节码编译成本地机器码的编译方式，和JIT的"运行时编译"正好相对。

## AOT vs JIT 核心对比

|维度|AOT（提前编译）|JIT（即时编译）|
|---|---|---|
|编译时机|程序运行前就编译好|程序运行过程中编译|
|启动速度|快，启动直接跑机器码|慢，需要预热|
|峰值性能|一般，缺少运行时信息|更高，可以基于profiling深度优化|
|编译信息|只有静态代码信息|有运行时数据，可以做激进优化|
|内存占用|编译产物存在磁盘，运行时加载|Code Cache占运行时内存|
|代表技术|JDK 9的jaotc、GraalVM Native Image、Excelsior JET|HotSpot C1/C2|

## JDK 9引入的jaotc工具

Java 9正式把AOT编译纳入官方特性，提供`jaotc`命令：

- 提前把`.class`或`.jar`编译成`.so`（Linux）或`.dylib`（Mac）动态库

- JVM启动时直接加载编译好的代码库，跳过解释和JIT预热阶段

- 主要目标是加快Java程序启动速度

## AOT的局限性

1. **无法动态优化**：没有运行时profile，做不了C2那种激进的优化

2. **兼容性问题**：编译产物和平台、JVM版本强绑定

3. **不支持动态类加载**：反射、动态代理生成的类没法提前编译

4. **编译产物大**：所有代码都编译，磁盘占用大

## 典型应用场景

1. **Serverless函数**：冷启动时间敏感，AOT启动快优势明显

2. **CLI命令行工具**：每次运行时间短，JIT还没预热就结束了

3. **容器化微服务**：快速启动、低内存占用的场景
