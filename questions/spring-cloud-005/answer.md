1. **解决服务寻址问题**：微服务架构下，服务实例的 IP 和端口是动态变化的（容器化部署、弹性伸缩），不能写死在配置文件里。注册中心让服务消费者能动态发现服务提供者的地址。

2. **支持动态扩缩容**：新加一台机器，启动后自动注册到注册中心；下线一台机器，自动从注册中心注销。服务消费者实时感知服务列表的变化。

3. **实现负载均衡的基础**：注册中心维护了所有服务实例的列表，客户端负载均衡器（Ribbon/LoadBalancer）从这个列表里选一个实例来调用。

4. **服务健康检查**：注册中心会定期检查服务实例的健康状态，不健康的实例会被剔除，不会再被调用到。

5. **解耦服务提供者和消费者**：提供者只需要注册到注册中心，不需要知道消费者是谁；消费者只需要从注册中心拉取服务列表，不需要知道提供者的具体地址。

## 扩展知识

- **服务注册流程**：服务启动时，向注册中心发送注册请求（服务名、IP、端口、元数据等）；运行期间定时发送心跳保持注册状态；关闭时发送注销请求。
- **服务发现流程**：消费者启动时从注册中心拉取服务列表并缓存到本地；之后定时增量更新；调用时从本地缓存中选一个实例。
- **AP vs CP**：Eureka 是 AP（高可用），Nacos 默认 AP 可切换 CP，Zookeeper 是 CP（强一致）。微服务场景一般选 AP，宁可拿到旧数据也不能拿不到。
