- **SDS（Simple Dynamic String）**：Redis 自己实现的字符串结构，是 Redis String 类型的底层实现（Redis 3.2 之前）。
- **SDS 结构**：
  - `len`：已使用字节数（字符串实际长度）
  - `alloc`：分配的总字节数（不含 `\0`）
  - `flags`：标识 SDS 类型（sdshdr5/8/16/32/64）
  - `buf[]`：实际存储字节数据的数组
- **与 C 字符串的区别**：
  - O(1) 获取长度（C 字符串需遍历，O(N)）
  - 二进制安全（可存任意数据，不以 `\0` 判断结束）
  - 杜绝缓冲区溢出（自动扩容）
  - 减少内存重分配（空间预分配 + 惰性释放）
- **Redis 3.2+ 改进**：引入多种 SDS 类型（sdshdr8/16/32/64），根据字符串长度选择不同头部，减少小字符串的内存开销。

## 扩展知识

**SDS 的空间预分配策略**：
- 当 SDS 长度 < 1MB 时，扩容后分配的空间 = 新长度 × 2
- 当 SDS 长度 >= 1MB 时，扩容后分配的空间 = 新长度 + 1MB
- 这种策略减少了内存重分配次数，提升了性能

**惰性释放策略**：
- 缩短字符串时不立即回收多余空间，而是用 `free` 字段记录
- 后续若需要扩容，可先使用 `free` 空间，避免频繁分配

**SDS 头部类型（Redis 3.2+）**：

| 类型 | 最大容量 | len/alloc 占用 | 适用场景 |
|------|---------|---------------|---------|
| sdshdr5 | 31 bytes | 无（仅1字节flag+data） | ≤31字节的小字符串 |
| sdshdr8 | 255 bytes | 各1字节 | 短字符串 |
| sdshdr16 | 65535 bytes | 各2字节 | 中等字符串 |
| sdshdr32 | 2^32-1 bytes | 各4字节 | 较大字符串 |
| sdshdr64 | 2^64-1 bytes | 各8字节 | 超大字符串 |

**EMBSTR 优化**：对于短字符串（≤44字节），Redis 使用 EMBSTR 编码，将 SDS 和 RedisObject 在一次内存分配中完成，减少内存碎片并提升缓存命中率。

## 对比表格

| 特性 | SDS | C 字符串 |
|------|-----|---------|
| 获取长度 | O(1) | O(N) |
| 二进制安全 | 是 | 否（以 `\0` 结尾） |
| 缓冲区溢出 | 自动扩容，不会溢出 | 可能溢出 |
| 内存分配策略 | 预分配 + 惰性释放 | 每次修改都重新分配 |
| 可修改性 | 动态 | 字面量不可修改 |
| 适用场景 | Redis 内部字符串 | C 语言原生文本处理 |
