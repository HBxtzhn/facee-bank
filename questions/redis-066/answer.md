- **Ziplist（压缩列表）**：一种将数据紧凑排列的连续内存编码结构，用于节省内存。每个节点存储前驱节点长度（`prevlen`）、当前节点编码信息和实际数据。支持双向遍历，通过首尾的 `zlbytes`、`zltail`、`zllen` 字段实现 O(1) 定位。
- **Quicklist（快速列表）**：Redis 3.2 引入，是 Ziplist 和双向链表的混合体。本质上是一个双向链表，每个节点是一个 Ziplist（Redis 7.0 后为 ListPack）。兼顾内存效率和操作性能。
- **Ziplist 的致命缺陷**：连锁更新（Cascading Update）问题。当某个节点长度从 `<254` 变为 `>=254` 时，`prevlen` 从 1 字节变为 5 字节，导致后续所有节点都需要重新分配内存，最坏 O(N²)。
- **Quicklist 的配置**：`list-max-ziplist-size` 控制每个 Ziplist 的最大大小（负值表示字节数限制，正值表示元素个数限制）；`list-compress-depth` 控制压缩层级（0 表示不压缩，N 表示最外层 N 个节点不压缩，中间节点用 LZ4 压缩）。

## 扩展知识

**Ziplist 的内部布局**：
```
| zlbytes(4B) | zltail(4B) | zllen(2B) | entry1 | entry2 | ... | zlend(1B) |
```
- `zlbytes`：整个 Ziplist 占用的字节数
- `zltail`：尾节点相对于起始地址的偏移量，用于 O(1) 定位尾节点
- `zllen`：节点数量，当超过 65535 时设为 0xFFFF，需遍历计算

**Entry 编码**：
- `prevlen`：前一个 entry 的长度，<254 用 1 字节，>=254 用 5 字节（首字节 0xFE + 4 字节实际长度）
- 数据编码：整数编码（16/32/64 位）、短字符串（len < 63 用 1 字节头）、长字符串（len >= 64 用 5 字节头）

**Quicklist 的设计哲学**：
- 将大 Ziplist 拆分为多个小 Ziplist，用双向链表串联
- 两端节点不压缩（频繁访问），中间节点可 LZ4 压缩（节省内存）
- 插入/删除只影响单个 Ziplist 节点，避免连锁更新的全局影响

## 对比表格

| 特性 | Ziplist | Quicklist |
|------|---------|-----------|
| 数据结构 | 连续内存块 | 双向链表 + Ziplist |
| 内存效率 | 极高（无指针开销） | 较高（有链表指针开销） |
| 插入/删除 | O(N)，可能触发连锁更新 | 平均 O(1) 定位 + O(N) 局部更新 |
| 遍历性能 | 连续内存，缓存友好 | 跨节点需跳转指针 |
| 连锁更新风险 | 有 | 仅影响单个节点内 |
| 压缩支持 | 不支持 | 中间节点支持 LZ4 压缩 |
| 适用场景 | 小数据量 | 通用 List 存储（默认） |
