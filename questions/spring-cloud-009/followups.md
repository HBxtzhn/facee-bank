## 追问 1：微服务拆分的粒度怎么把握？

太粗了跟单体没区别，太细了运维成本爆炸。我的原则是：按 DDD 限界上下文拆，一个服务对应一个业务域；一个服务一个团队能维护（两个披萨原则）；服务之间的依赖关系尽量少。可以先粗后细，先按大模块拆，随着业务增长再细化。

## 追问 2：微服务之间数据怎么共享？

不能共享数据库，每个服务有自己的数据库。如果服务 A 需要服务 B 的数据，通过调用服务 B 的 API 获取。对于需要跨服务查询的场景，可以通过 CQRS（命令查询职责分离）模式，把数据同步到查询专用的数据库里。数据同步可以用 MQ 事件驱动或者 CDC（Change Data Capture）工具。

## 追问 3：微服务架构下怎么做测试？

分几层：单元测试用 JUnit + Mockito 测单个服务的业务逻辑；集成测试用 Testcontainers 启动依赖的中间件测服务跟数据库/MQ的交互；契约测试用 Pact 验证服务之间的接口兼容性；端到端测试在测试环境模拟真实调用链路。
