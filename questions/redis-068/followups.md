## 追问 1：Redis 事务中某条命令执行出错，会发生什么？

分两种情况：① 入队阶段出错（语法错误等），整个事务被拒绝，`EXEC` 返回错误；② 执行阶段出错（如对 String 类型执行 `LPUSH`），只有该命令报错，其余命令正常执行。Redis 不会回滚已执行的命令。这是 Redis 的设计选择——追求简单高效，将一致性责任交给应用层。

## 追问 2：WATCH 和 Lua 脚本在实现原子操作上有什么区别？

WATCH 是乐观锁，适合"读-改-写"场景，冲突时需要重试，高并发下重试率高性能下降。Lua 脚本在服务端原子执行（单线程保证），执行期间不会被其他命令打断，无需重试，适合复杂原子操作。但 Lua 脚本执行时间过长会阻塞其他命令，建议控制在毫秒级。

## 追问 3：如果需要 Redis 事务的原子性保证，有什么替代方案？

① 使用 Lua 脚本将多条命令封装为一个原子操作；② 使用 `WATCH` + 重试机制实现乐观锁；③ 使用 Redis 7.0 的 Function 机制；④ 业务层做补偿（记录操作日志，失败时反向操作）。对于强一致性场景，建议使用分布式事务框架（如 Seata）配合持久化数据库。
