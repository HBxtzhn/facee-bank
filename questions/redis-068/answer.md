- **原子性**：Redis 事务保证命令的**顺序执行**，但不保证原子性。执行过程中某条命令报错，其余命令仍会继续执行（不回滚）。关系型数据库事务保证原子性，任一操作失败则全部回滚。
- **隔离性**：Redis 单线程执行事务（`EXEC` 阶段），天然串行化，不存在并发冲突。关系型数据库需要锁机制（行锁、表锁、MVCC）来实现隔离级别。
- **持久性**：Redis 事务的持久性取决于 RDB/AOF 策略。异步 AOF 模式下，`EXEC` 后数据可能因宕机丢失。关系型数据库通过 WAL（Write-Ahead Log）保证持久性。
- **一致性**：Redis 事务不做约束检查（如唯一性约束），一致性由业务层保证。关系型数据库通过约束、触发器等保证数据一致性。

## 扩展知识

**Redis 事务的执行流程**：
1. `MULTI`：开启事务，客户端进入事务上下文
2. 后续命令入队（返回 `QUEUED`），不立即执行
3. `EXEC`：按顺序执行队列中所有命令
4. `DISCARD`：放弃事务，清空命令队列

**WATCH 乐观锁机制**：
- `WATCH key`：监视一个或多个 key，当 `EXEC` 时如果被监视的 key 被其他客户端修改，事务执行失败（返回 nil）
- 本质是 CAS（Check-And-Set）操作
- 失败后需重试，属于乐观锁思想

**Redis 7.0 的 FUNCTION 与事务**：
Redis 7.0 引入的 Function 可以在服务端原子执行一段 Lua 脚本，比事务更灵活，且 Lua 脚本执行期间阻塞其他命令，天然原子。

## 对比表格

| 特性 | Redis 事务 | 关系型数据库事务 |
|------|-----------|----------------|
| 原子性 | 不保证（命令错误不回滚） | 完全保证（失败全部回滚） |
| 隔离性 | 天然隔离（单线程串行） | 需锁/MVCC 实现 |
| 持久性 | 依赖 AOF/RDB 策略 | WAL 保证 |
| 一致性 | 业务层保证 | 数据库约束保证 |
| 回滚能力 | 不支持 | 支持 undo log 回滚 |
| 锁机制 | WATCH 乐观锁 | 悲观锁 + 乐观锁 |
| 嵌套事务 | 不支持 | 支持（保存点） |
| 性能 | 极高（批量执行减少 RTT） | 相对较低（锁开销大） |
