- **最大容量**：Redis String 类型的最大值为 **512MB**（2^32 - 1 字节，实际为 512MB = 2^29 字节，由 SDS 的 `len` 字段类型决定）。
- **准确说法**：String 值最大为 `2^32` 字节 = 4GB（Redis 官方文档说明），但受 SDS 头部类型限制：
  - sdshdr8：最大 255 字节
  - sdshdr16：最大 64KB
  - sdshdr32：最大 4GB（实际限制约 512MB，受 Redis 内存和配置约束）
- **实际限制**：
  - 单个 String 值不建议超过几 MB，否则会影响性能（大 key 问题）
  - Redis 是单线程处理命令，操作大 value 会阻塞其他命令
  - 网络传输大 value 也会造成延迟

## 扩展知识

**大 Key 问题的危害**：
- 写入时：单个命令执行时间过长，阻塞其他客户端
- 删除时：`DEL` 大 key 会阻塞主线程（可用 `UNLINK` 异步删除）
- 内存不均：Cluster 模式下大 key 可能导致某个节点内存过高
- 主从延迟：大 key 同步到从节点耗时更长

**大 Key 的优化方案**：
- 拆分：将大 String 拆分为多个小 key（如按字段分片）
- 压缩：使用 `SET key value` 前先用 GZIP/Snappy 压缩
- 替代结构：使用 Hash 代替大 JSON 字符串
- 异步删除：使用 `UNLINK` 代替 `DEL`

**Redis 内存限制**：
- `maxmemory` 配置项限制 Redis 实例最大内存
- 超出后根据淘汰策略（`maxmemory-policy`）处理

## 对比表格

| 数据类型 | 最大容量 | 建议上限 | 大值风险 |
|---------|---------|---------|---------|
| String | 512MB | < 10KB | 阻塞、内存不均 |
| Hash | 2^32 - 1 个字段 | < 100 个字段 | 同上 |
| List | 2^32 - 1 个元素 | < 5000 个元素 | 同上 |
| Set | 2^32 - 1 个成员 | < 5000 个成员 | 同上 |
| ZSet | 2^32 - 1 个成员 | < 5000 个成员 | 同上 |
