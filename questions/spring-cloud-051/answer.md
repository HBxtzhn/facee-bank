1. **定义**：API 网关是系统的统一入口，所有客户端请求先到达网关，网关负责请求的路由、鉴权、限流、监控等，然后把请求转发到对应的后端服务。网关是微服务架构的"门面"。

2. **核心作用**：
   - **路由转发**：根据请求的 URL、Header 等条件，把请求转发到对应的后端服务。客户端不需要知道后端服务的地址。
   - **鉴权认证**：统一做身份认证（JWT/OAuth2/API Key），后端服务不需要重复实现。
   - **限流熔断**：限制入口流量，防止系统被压垮；下游服务不可用时快速失败。
   - **协议转换**：外部用 HTTP/HTTPS，内部可能用 gRPC/Dubbo，网关做协议转换。
   - **日志监控**：统一记录请求日志、调用耗时、错误率，方便排查问题和性能分析。
   - **跨域处理**：统一处理 CORS，后端服务不需要单独配置。
   - **请求/响应改写**：在网关层统一添加/删除请求头、改写 URL、转换数据格式。

3. **网关的位置**：客户端 → API 网关 → 微服务集群。网关是系统的唯一入口（Single Entry Point）。

4. **网关的分类**：微服务网关（Spring Cloud Gateway、Kong，面向内部微服务路由）和 API 管理平台（Kong、APISIX，面向对外开放 API）。

## 扩展知识

- **网关的设计原则**：网关应该尽量轻量，不做复杂的业务逻辑。核心职责是路由、安全、流量管控。业务逻辑应该在后端服务里。
- **网关的高可用**：网关是单点，必须做集群部署 + 负载均衡。一般至少 2 个节点，前面挂 Nginx 或云厂商的 SLB。
- **网关的性能瓶颈**：网关是所有请求的入口，性能至关重要。选择异步非阻塞的网关（Gateway、APISIX），避免同步阻塞的（Zuul 1.x）。
