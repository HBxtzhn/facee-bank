1. **分散请求压力**：单台服务器的处理能力有限，通过负载均衡把请求分发到多台服务器，避免单台过载。

2. **提高可用性**：某台服务器挂了，负载均衡自动把请求转发到其他健康的服务器，用户无感知。

3. **弹性扩展**：业务量增长时，加服务器就行，负载均衡自动把新服务器纳入分发范围。

4. **提升性能**：通过合理的负载均衡算法，让每台服务器的负载相对均匀，避免"忙的忙死、闲的闲死"。

5. **微服务场景**：微服务架构下，一个服务通常有多个实例，负载均衡决定每次调用选哪个实例，直接影响系统的性能和可用性。

## 扩展知识

- **负载均衡的分类**：按位置分为服务端负载均衡（Nginx、F5、HAProxy）和客户端负载均衡（Ribbon、Spring Cloud LoadBalancer）。按协议分为四层负载均衡（TCP/UDP）和七层负载均衡（HTTP）。
- **微服务中的负载均衡**：Spring Cloud 用的是客户端负载均衡，消费者从注册中心拿到服务列表，在本地通过负载均衡算法选一个实例调用。不需要额外的负载均衡服务器，减少了网络跳转。
