- **批量命令列表**：
  - `MSET key1 value1 key2 value2 ...`：批量设置多个 key-value
  - `MGET key1 key2 ...`：批量获取多个 key 的值
  - `MSETNX key1 value1 key2 value2 ...`：批量设置，所有 key 都不存在时才设置（原子操作）
  - `DEL key1 key2 ...`：批量删除（虽然不是专门的批处理命令，但支持多参数）
  - `EXISTS key1 key2 ...`：批量判断 key 是否存在（Redis 3.0.3+）
  - `UNLINK key1 key2 ...`：批量异步删除（Redis 4.0+）
- **原子性**：`MSET` 和 `MSETNX` 是原子操作，所有 key 在同一时刻被设置。
- **Pipeline vs 批量命令**：Pipeline 是客户端层面的批量发送，支持任意命令组合；MSET/MGET 是服务端原生命令，仅限特定操作。

## 扩展知识

**MSET 的原子性保证**：
- MSET 在服务端一次性执行，要么全部成功，要么全部失败
- 不会出现部分 key 设置成功、部分失败的情况
- 但 MSET 不支持事务回滚（不像 MULTI/EXEC 可以 WATCH）

**MSETNX 的特殊行为**：
- 如果任意一个 key 已存在，则所有 key 都不会被设置
- 返回值：1 表示全部设置成功，0 表示失败（有 key 已存在）
- 常用于实现简单的分布式锁（但不推荐，因为没有过期时间）

**Pipeline 的优势**：
- 减少网络 RTT（Round Trip Time）
- 可以混合不同类型的命令
- 客户端层面实现，不要求命令之间有原子性
- 配合 MSET/MGET 使用效果更佳

**批量操作的注意事项**：
- 批量大小不宜过大（建议 500~1000 个），否则单次命令执行时间过长
- Cluster 模式下，批量操作的 key 可能分布在不同 slot，需要使用 `{hashtag}` 保证同 slot 或使用客户端的集群感知能力

## 对比表格

| 命令 | 功能 | 原子性 | 返回值 |
|------|------|--------|--------|
| MSET | 批量设置 | 是 | 固定 OK |
| MGET | 批量获取 | 是 | 值列表（不存在的返回 nil） |
| MSETNX | 批量设置（不存在时） | 是 | 1 成功 / 0 失败 |
| Pipeline | 批量发送任意命令 | 否（逐条执行） | 各命令结果列表 |
| MULTI/EXEC | 事务 | 是 | 各命令结果列表 |
