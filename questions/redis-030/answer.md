- **数据分片**：Redis Cluster 采用哈希槽（hash slot）机制，共 16384 个槽。每个 key 通过 `CRC16(key) % 16384` 计算所属槽，再映射到对应的节点。
- **节点通信**：集群节点之间通过 Gossip 协议交换状态信息（`PING`/`PONG`/`MEET`/`FAIL`），维护集群元数据。
- **故障检测**：当集群中半数以上主节点认为某节点不可达时，该节点被标记为 `FAIL`；若该节点是主节点，其从节点会发起选举，由其他主节点投票选出新的主节点（基于 Raft 类似协议）。
- **客户端重定向**：当客户端访问了错误节点，节点返回 `MOVED` 重定向（永久迁移）或 `ASK` 重定向（迁移中临时转发），客户端据此路由到正确节点。

## 扩展知识

- **哈希槽分配**：每个主节点负责一部分槽，例如 3 个节点分别负责 0-5460、5461-10922、10923-16383。槽的迁移是原子性的，以单个 key 为粒度进行。
- **MOVED vs ASK**：`MOVED` 表示槽已永久迁移到新节点，客户端应更新本地路由表；`ASK` 表示槽正在迁移中，客户端应临时向目标节点发送 `ASKING` 命令后再执行命令。
- **集群模式限制**：不支持跨槽的多 key 操作（除非使用 `{hashtag}` 强制同槽）；不支持 `SELECT` 多数据库；批量操作受限。
- **Gossip 消息**：包括 `MEET`（加入集群）、`PING`/`PONG`（心跳）、`FAIL`（标记故障）、`UPDATE`（槽配置更新）等，消息体包含发送者已知的其他节点状态，实现去中心化信息传播。
