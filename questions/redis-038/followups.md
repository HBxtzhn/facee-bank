## 追问 1：Redis 事务为什么不支持回滚？

Redis 团队认为：① 命令执行失败通常是因为使用错误（如类型不匹配），这种错误应在开发/测试阶段发现，而非运行时；② 支持回滚会增加实现复杂度，与 Redis 简洁的设计哲学相悖；③ 单线程模型下，事务中的命令按顺序执行，不存在并发导致的不一致。

## 追问 2：WATCH 的 CAS 操作如何实现？如果 WATCH 失败怎么办？

客户端通过循环实现 CAS：`WATCH key` → `GET key` → `MULTI` → `SET key new_value` → `EXEC`。若 EXEC 返回 nil（key 被修改），则重试整个流程。通常设置最大重试次数避免活锁。

## 追问 3：Lua 脚本和事务各有什么优劣？如何选择？

Lua 脚本：支持条件判断和错误处理，原子执行，适合复杂逻辑；事务：语法简单，适合批量执行独立命令。需要条件判断或强原子性时用 Lua；简单的批量操作用事务。
