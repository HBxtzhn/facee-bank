- **基本事务**：Redis 通过 `MULTI`/`EXEC`/`DISCARD`/`WATCH` 实现事务。`MULTI` 开启事务，后续命令入队不执行；`EXEC` 一次性按顺序执行所有命令；`DISCARD` 取消事务。
- **原子性**：Redis 事务保证命令的批量提交和顺序执行，但**不支持回滚**。如果某条命令执行失败（运行时错误），其余命令仍会继续执行。
- **乐观锁（WATCH）**：`WATCH key` 监视一个或多个 key，若事务执行前这些 key 被其他客户端修改，`EXEC` 返回 nil（事务失败），客户端可重试。
- **语法错误**：如果事务中存在语法错误（如命令不存在），整个事务会被拒绝，所有命令都不会执行。

## 扩展知识

- **事务 vs 传统数据库事务**：Redis 事务不支持隔离级别（因为单线程串行执行，天然隔离）；不支持回滚（设计哲学：保持简单，错误应在开发阶段发现）。
- **WATCH 实现原理**：WATCH 将 key 标记为 dirty，每次有命令修改该 key 时设置标志位。EXEC 时检查所有被 WATCH 的 key 是否被修改，若被修改则拒绝执行。
- **Lua 脚本替代事务**：对于需要原子性的复杂操作，推荐使用 Lua 脚本（`EVAL`），Lua 脚本在 Redis 中以原子方式执行，支持错误处理和条件判断，比事务更灵活。

## 对比表格

| 特性 | Redis 事务 | 传统数据库事务 |
|------|-----------|--------------|
| 原子性 | 部分（不支持回滚） | 完全（支持回滚） |
| 隔离性 | 天然隔离（单线程） | 需锁/MVCC 实现 |
| 持久性 | 取决于持久化配置 | 支持（WAL） |
| 一致性 | 不保证回滚后一致性 | 完全保证 |
| 乐观锁 | WATCH | 版本号 / 时间戳 |
| 回滚 | 不支持 | 支持 |
