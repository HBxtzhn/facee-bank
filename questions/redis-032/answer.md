- **纯内存操作**：所有数据存储在内存中，读写操作无需磁盘 I/O，内存访问速度是磁盘的 10 万倍以上。
- **单线程模型**：避免了多线程上下文切换和锁竞争的开销，CPU 不是 Redis 的瓶颈，内存和网络才是。
- **I/O 多路复用**：使用 epoll（Linux）/ kqueue（BSD）/ select（Windows）实现非阻塞 I/O，单线程同时处理大量客户端连接。
- **高效数据结构**：针对场景设计了专用数据结构，如 SDS（简单动态字符串）、跳表、压缩列表、整数集合、快速列表等，在时间和空间上都做了优化。
- **通信协议简单**：RESP 协议解析开销小，文本协议但解析效率高于 JSON/XML。

## 扩展知识

- **SDS vs C 字符串**：SDS 记录 `len` 和 `free`，获取长度 O(1)；支持二进制安全；预分配机制减少内存重分配（空间预分配 + 惰性释放）。
- **I/O 多路复用详解**：Redis 的事件循环（`aeEventLoop`）注册文件事件和定时事件。文件事件处理器包含：连接应答处理器、命令请求处理器、命令回复处理器。单线程串行处理命令，保证原子性。
- **渐进式 rehash**：哈希表扩容时不一次性迁移，而是在每次增删改查时分批迁移，避免一次性 rehash 造成阻塞。
- **内存布局优化**：小对象使用紧凑编码（如 `ziplist`、`intset`、`listpack`），减少内存碎片和指针开销。
