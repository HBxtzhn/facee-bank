## 追问 1：单线程为什么能处理高并发？

Redis 单线程指的是命令处理线程为单线程（网络 I/O 和协议解析在 Redis 6.0 后由多线程处理）。由于操作都在内存中，单条命令执行极快（微秒级），配合 I/O 多路复用，单线程每秒可处理 10 万+ 请求。瓶颈在网络带宽和内存带宽，而非 CPU。

## 追问 2：Redis 6.0 引入多线程会不会影响性能？

多线程仅用于网络 I/O（读写 socket 和协议解析），命令执行仍然是单线程串行，因此不会引入锁竞争，保证了原子性语义。实测吞吐量提升约 1 倍（从 10w QPS 到 20w+ QPS）。

## 追问 3：Redis 的 event loop 是如何工作的？

Redis 自定义事件库 `ae`，核心循环：① 处理到期的时间事件（如 `serverCron`）；② 通过 `epoll_wait` 等待文件事件就绪；③ 处理就绪的文件事件（读命令 → 执行命令 → 写响应）；④ 循环。每次循环前还会处理 `beforeSleep` 中的批量操作（如 AOF 刷盘、复制积压缓冲区写入）。
