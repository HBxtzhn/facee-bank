1. **灰度发布（Gray Release）**：在新老版本之间按一定策略（按比例、按用户、按地域）分配流量，一部分用户用新版本，一部分用老版本。观察新版本的运行情况，没问题再逐步扩大流量，最终全量发布。也叫金丝雀发布。

2. **金丝雀部署（Canary Deployment）**：跟灰度发布本质相同。先部署一个"金丝雀"版本（新版本），引入少量流量（比如5%），观察监控指标（错误率、响应时间），没问题再逐步增加流量比例，最终替代老版本。

3. **蓝绿部署（Blue-Green Deployment）**：同时维护两套环境（蓝色和绿色）。当前生产环境是蓝色（老版本），新版本部署在绿色环境。通过切换路由（负载均衡/Nginx），把流量从蓝色切到绿色。切换后绿色成为生产环境，蓝色保留作为回滚备份。

4. **区别**：灰度/金丝雀是渐进式的（流量从小到大逐步切换），蓝绿是一次性的（全量切换）。灰度可以按用户特征（VIP 用户先用新版），蓝绿是全量切换。灰度回滚影响部分用户，蓝绿回滚是整体切换。

## 概念对比

| 特性 | 灰度/金丝雀 | 蓝绿部署 |
|------|------------|----------|
| 流量切换 | 渐进式（5%→20%→50%→100%） | 一次性（全量切换） |
| 并行环境 | 新老版本同时运行 | 两套完整环境同时运行 |
| 回滚速度 | 快（减少流量比例） | 很快（切回老环境） |
| 资源消耗 | 中（新老版本共享部分资源） | 高（需要两套完整环境） |
| 适用场景 | 大流量、需要逐步验证 | 简单快速切换、资源充足 |

## 扩展知识

- **灰度发布的实现**：通过网关（Gateway）或注册中心（Nacos）的路由规则实现。Nacos 支持按元数据路由（给灰度实例打 
ersion=gray 标签），Gateway 根据请求头或用户属性路由到不同版本的实例。
- **全链路灰度**：不仅网关层做灰度，微服务之间的调用也要做灰度。比如请求路由到灰度网关，网关调用灰度的订单服务，订单服务调用灰度的库存服务。需要链路追踪的 TraceId 或自定义 Header 在整个调用链中传递。
- **A/B 测试**：灰度发布的一种特殊形式，不仅验证新版本的稳定性，还对比新老版本的业务指标（转化率、用户满意度），用数据决策是否全量发布。
