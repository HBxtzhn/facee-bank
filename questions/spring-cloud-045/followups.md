## 追问 1：你的项目里灰度发布是怎么做的？

通过 Nacos 的元数据 + Gateway 的路由规则实现。灰度实例在 Nacos 注册时打上 
ersion=gray 的元数据标签。Gateway 层根据请求头里的 X-Gray-Version 或用户 ID 的 hash 值，决定路由到灰度实例还是正式实例。灰度流量比例通过配置中心动态调整（5%→20%→50%→100%）。

## 追问 2：全链路灰度怎么实现？

需要三个条件：第一，网关层按规则路由到灰度实例；第二，请求头里带上灰度标识（X-Gray-Version），通过 Feign 拦截器在整个调用链中传递；第三，每个微服务根据请求头里的灰度标识，从注册中心选择对应版本的实例调用。Nacos 的元数据路由和 Spring Cloud LoadBalancer 的自定义路由规则可以实现。

## 追问 3：蓝绿部署的缺点是什么？

主要缺点是需要两套完整的环境，资源消耗翻倍。对于大型系统，两套环境意味着双倍的服务器成本。另外，蓝绿是全量切换，如果新版本有问题，影响所有用户。灰度发布可以逐步切换，影响范围可控。所以大流量场景一般用灰度，小项目或者内部系统可以用蓝绿。
