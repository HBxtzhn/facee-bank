1. **定义**：服务限流是限制单位时间内进入系统的请求数量，超过限制的请求被拒绝或排队等待。目的是保护系统不被过大的流量压垮。

2. **为什么要限流**：
   - 防止突发流量压垮系统（比如秒杀、大促）
   - 防止恶意攻击（CC 攻击、爬虫）
   - 保护下游服务不被过载
   - 保证核心服务的可用性（牺牲非核心请求）

3. **限流算法**：
   - **固定窗口计数器**：把时间分成固定窗口（比如1秒），每个窗口内允许 N 个请求。简单但有临界问题（窗口边界可能通过 2N 个请求）。
   - **滑动窗口计数器**：把窗口细分成多个小格，滑动统计。解决了固定窗口的临界问题。
   - **漏桶算法（Leaky Bucket）**：请求进入桶中，以固定速率流出处理。可以平滑流量，但不能处理突发流量。
   - **令牌桶算法（Token Bucket）**：以固定速率往桶里放令牌，请求需要拿到令牌才能处理。可以处理突发流量（桶里有囤积的令牌），也能限制平均速率。

4. **限流维度**：QPS 限流（每秒请求数）、并发线程数限流、热点参数限流（针对某个参数值限流，比如某个商品ID）。

## 扩展知识

- **Sentinel 限流**：Sentinel 支持 QPS 限流（匀速排队、快速失败、Warm Up 预热）、线程数限流、热点参数限流、系统自适应保护（根据系统负载自动限流）。
- **分布式限流**：单机限流只能限制单个实例的流量，分布式限流限制整个集群的总流量。Sentinel 通过 Token Server 实现集群限流。
- **网关限流**：在 API 网关（Gateway）层面做限流，限制某个 API 或某个用户的总流量。Spring Cloud Gateway 集成 Sentinel 或 Redis + Lua 实现。

## 概念对比

| 算法 | 原理 | 特点 | 适用场景 |
|------|------|------|----------|
| 固定窗口 | 时间窗口计数 | 简单，有临界问题 | 要求不高的场景 |
| 滑动窗口 | 滑动时间窗口计数 | 精确，开销稍大 | 精确限流 |
| 漏桶 | 固定速率处理 | 平滑流量，不能突发 | 匀速处理 |
| 令牌桶 | 固定速率生成令牌 | 允许突发，限制平均速率 | 大部分场景 |
