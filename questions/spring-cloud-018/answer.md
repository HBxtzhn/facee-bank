1. **Eureka**：Netflix 开源，Spring Cloud 早期默认的注册中心。AP 模型（高可用），节点之间通过复制（replication）保持数据一致。已经停止维护，不推荐新项目使用。

2. **Nacos**：阿里开源，既能做注册中心又能做配置中心。支持 AP 和 CP 模式切换（默认 AP，临时实例用 Distro 协议；持久实例用 Raft 协议）。国内用的最多。

3. **Consul**：HashiCorp 开源，基于 Go 语言，CP 模型（强一致），使用 Raft 协议。支持健康检查、KV 存储、多数据中心。适合对一致性要求高的场景。

4. **Zookeeper**：Apache 顶级项目，CP 模型，使用 ZAB 协议（类 Raft）。在 Dubbo 生态中用的多，Spring Cloud 里用的少。适合对一致性要求高、对可用性要求相对低的场景。

5. **选型建议**：国内首选 Nacos，功能全、社区活跃、中文文档好。如果已经用了 Dubbo + Zookeeper，可以继续用 ZK。Consul 适合多数据中心场景。

## 概念对比

| 特性 | Eureka | Nacos | Consul | Zookeeper |
|------|--------|-------|--------|-----------|
| 一致性模型 | AP | AP/CP 可切换 | CP | CP |
| 健康检查 | 心跳 | 心跳/TCP/HTTP | 多种策略 | KeepAlive |
| 配置中心 | 不支持 | 支持 | 支持（KV） | 支持（KV） |

| 社区活跃度 | 停更 | 活跃 | 活跃 | 活跃 |
| 语言 | Java | Java | Go | Java |

## 扩展知识

- **AP vs CP 的选择**：微服务注册发现场景，宁可拿到旧的服务列表（AP），也不能拿不到（CP）。所以大部分情况用 AP 模式。但如果是需要强一致的场景（比如分布式锁），用 CP 模式。
- **Nacos 的临时实例和持久实例**：临时实例（默认）用 AP 模式，客户端通过心跳维持注册，适合大部分微服务场景；持久实例用 CP 模式，服务端主动探测，适合需要强一致的场景。
