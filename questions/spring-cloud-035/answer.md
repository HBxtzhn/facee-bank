1. **定义**：熔断器（Circuit Breaker）是一种保护机制，当下游服务不可用或响应过慢时，自动"断开"调用（熔断），直接返回降级数据，避免调用方一直等待或重试导致资源耗尽。

2. **为什么要用**：微服务架构下，服务之间互相调用，如果下游服务挂了或响应很慢，上游服务会一直等待或重试，导致上游服务的线程池被占满、内存被耗尽，最终上游服务也挂了——这就是服务雪崩。熔断器就是防止服务雪崩的。

3. **三种状态**：
   - **关闭（Closed）**：正常状态，请求正常通过。熔断器会统计请求的失败率。
   - **打开（Open）**：失败率超过阈值，熔断器打开，后续请求直接走降级逻辑，不实际调用下游服务。
   - **半开（Half-Open）**：经过一段时间后（冷却期），熔断器进入半开状态，放行少量请求试探下游是否恢复。如果成功，关闭熔断器；如果失败，重新打开。

4. **类比**：电路里的保险丝。电流过大时保险丝熔断，保护电器不被烧坏。故障排除后换上新保险丝（或自动恢复），电路恢复正常。

## 扩展知识

- **熔断 vs 降级**：熔断是自动触发的（失败率超过阈值自动打开），降级可以是自动的（熔断触发降级）也可以是手动的（主动降级返回兜底数据）。熔断是手段，降级是结果。
- **熔断器的配置参数**：失败率阈值（比如 50%）、慢调用比例阈值（比如响应时间超过3秒算慢调用）、冷却时间（熔断后多久进入半开状态）、半开状态允许的请求数。
- **生产实践**：熔断器一般配合降级使用——熔断触发后返回缓存数据、默认值或友好的错误提示。关键服务要配置熔断，非关键服务可以宽松一些。
