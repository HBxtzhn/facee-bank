## 追问 1：缓存和数据库双写一致性如何保证？

常用方案：① 先更新 DB，再删除缓存（Cache-Aside），配合重试机制保证删除成功；② 延迟双删：先删缓存 → 更新 DB → 延迟一段时间再删缓存；③ 基于 binlog（Canal）异步更新缓存，最终一致性。强一致场景可用分布式锁。

## 追问 2：分布式锁用 Redis 实现有什么缺陷？

① 锁超时但业务未完成，可能误删他人锁（解决：UUID + Lua 脚本校验）；② 主从切换导致锁丢失（解决：Redlock 算法，多数节点加锁成功才算获得锁）；③ 不可重入（解决：用 hash 记录重入次数，如 Redisson）。对一致性要求极高的场景建议使用 ZooKeeper。

## 追问 3：如何用 Redis 实现滑动窗口限流？

使用 ZSet：以时间戳为 score，每次请求 `ZADD` 当前时间戳，再 `ZREMRANGEBYSCORE` 移除窗口外的记录，最后 `ZCARD` 统计窗口内请求数，超过阈值则拒绝。时间复杂度 O(log N)。
