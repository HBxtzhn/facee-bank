- **常见拓扑结构**：
  1. **一主一从**：最简单的结构，主节点负责写，从节点负责读和备份。
  2. **一主多从**：一个主节点 + 多个从节点，读写分离，从节点分担读压力。
  3. **级联复制（链式复制）**：主 → 从1 → 从2，减少主节点的复制连接数，但增加延迟。
  4. **树状复制**：主节点下挂多个从节点，每个从节点再挂子从节点。
  5. **Redis Cluster**：多主多从的分片集群，每个主节点负责一部分 slot，每个主节点有至少一个从节点。
- **复制过程**：
  - **全量复制**：从节点首次连接主节点时，主节点执行 `BGSAVE` 生成 RDB 快照发送给从节点
  - **增量复制**：全量复制后，主节点将后续写命令通过 repl_backlog 同步给从节点

## 扩展知识

**全量复制流程**：
1. 从节点发送 `PSYNC ? -1`（全量同步请求）
2. 主节点执行 `BGSAVE` 生成 RDB 快照（fork 子进程，不阻塞主线程）
3. 主节点将 RDB 快照发送给从节点
4. 从节点加载 RDB 到内存
5. 主节点将复制期间积累的写命令发送给从节点执行

**增量复制流程**：
- 主节点维护 `repl_backlog`（默认 1MB），记录最近的写命令
- 从节点断线重连后发送 `PSYNC <runid> <offset>`
- 如果 offset 范围内的数据还在 repl_backlog 中，执行增量复制（partial resync）
- 否则退化为全量复制

**哨兵模式（Sentinel）**：
- 监控主从节点健康状态
- 主节点故障时自动将从节点提升为新主节点
- 客户端通过 Sentinel 发现当前主节点地址

## 对比表格

| 拓扑结构 | 优点 | 缺点 | 适用场景 |
|---------|------|------|---------|
| 一主一从 | 简单、易维护 | 读扩展有限、单点风险 | 开发测试、小项目 |
| 一主多从 | 读扩展好、冗余高 | 写能力不扩展、主节点压力大 | 读多写少场景 |
| 级联复制 | 减轻主节点复制压力 | 末端从节点延迟高 | 跨机房、从节点数量多 |
| Redis Cluster | 水平扩展、高可用 | 运维复杂、跨 slot 操作受限 | 大规模生产环境 |
