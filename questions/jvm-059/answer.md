**Logging Write Barrier（日志式写屏障）**，也叫**SATB写屏障**，是G1垃圾收集器中用于支持原始快照（SATB）算法的写屏障实现。

## 写屏障是什么

写屏障不是内存屏障，而是JVM在每次对象引用赋值前后插入的一小段额外代码，类似AOP的拦截。目的是在引用变化时通知GC，记录下变化信息。

```java
// 原始代码
obj.field = newObj;

// 插入写屏障后
write_barrier(obj, field, newObj); // 写屏障：记录引用变化
obj.field = newObj;
```

## Logging Write Barrier的工作方式

G1的SATB写屏障在引用被覆盖前，先把旧引用记录下来：

1. **赋值前拦截**：在给对象字段赋新值之前，先拿到旧的引用值

2. **记录旧引用**：如果旧引用指向的对象是白色的（还没标记），就把这个旧引用对象加入SATB队列

3. **后续处理**：并发标记结束后，扫描SATB队列，把这些旧引用对象都标记为存活

## 为什么叫"Logging"（日志式）

因为它的工作方式像写日志一样：

- 引用变化时不做复杂处理，只是简单地把旧值写到队列（日志）里

- 记录操作很快，不阻塞赋值操作太久

- 后面批量处理这个日志队列

是一种**写时记录、批量处理**的思路，把开销摊平，减少写屏障对赋值性能的影响。

## 和CMS写屏障的区别

|写屏障类型|对应收集器|记录内容|目的|
|---|---|---|---|
|卡表写屏障|CMS|标记脏卡|记录老年代跨代引用|
|Logging/SATB写屏障|G1|记录被删除的旧引用|支持SATB原始快照标记|
|日志式写屏障|G1|记录新引用到RSet|维护Region间的引用关系|

注意：G1其实有两类写屏障，一类维护SATB标记，一类维护RSet。Logging write barrier通常指SATB那类。
