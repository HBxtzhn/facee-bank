## 追问 1：服务网格适合什么场景？

适合多语言混合的微服务架构。如果团队以 Java 为主，Spring Cloud 就够用了，引入服务网格反而增加复杂度。如果团队有多种语言（Java + Go + Python），服务网格可以提供统一的服务治理方案，不需要每种语言都实现一套 SDK。

## 追问 2：服务网格的性能影响有多大？

Sidecar 代理会增加一跳网络延迟（一般 1-3ms），加上 Sidecar 本身的资源消耗（CPU 和内存）。对于大部分业务场景，这个影响可以忽略。但对于超低延迟的场景（比如高频交易），可能需要评估。Istio 也在持续优化性能，比如用 eBPF 技术绕过 Sidecar。

## 追问 3：你的项目里用了服务网格吗？

没用。团队以 Java 为主，用 Spring Cloud + Sentinel 就能满足服务治理需求，引入 Istio 反而增加运维复杂度。但如果未来团队扩展到其他语言，或者需要更细粒度的流量控制（比如跨语言的灰度发布），会考虑引入服务网格。
