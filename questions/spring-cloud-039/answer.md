1. **定义**：服务熔断是一种自动保护机制，当下游服务的失败率或慢调用比例超过阈值时，自动"断开"对该服务的调用（像电路保险丝一样熔断），后续请求直接走降级逻辑，不再实际调用下游服务。

2. **熔断的目的**：防止服务雪崩。下游服务已经不可用了，上游还不断调用只会浪费资源（线程、连接），最终把自己也拖垮。熔断后快速失败，释放资源，给下游恢复的时间。

3. **熔断策略（Sentinel）**：
   - **慢调用比例**：响应时间超过阈值的请求比例超过设定值，触发熔断。比如 RT 超过 3 秒的请求占比超过 50%。
   - **异常比例**：异常请求（业务异常或超时）的比例超过设定值，触发熔断。比如异常比例超过 30%。
   - **异常数**：异常请求的绝对数量超过设定值，触发熔断。比如1分钟内异常数超过10个。

4. **熔断恢复**：熔断后进入冷却期（比如10秒），冷却期结束后进入半开状态，放行一个请求试探。成功则关闭熔断，失败则重新熔断。

5. **熔断 vs 降级**：熔断是自动触发的保护机制（检测到故障），降级是熔断后的处理方式（返回兜底数据）。熔断是手段，降级是结果。

## 扩展知识

- **Sentinel 熔断配置示例**：

``java
@SentinelResource(value = "getOrder",
    fallback = "getOrderFallback",       // 业务异常降级
    blockHandler = "getOrderBlockHandler" // 限流/熔断降级
)
public Order getOrder(Long id) {
    return orderClient.getOrder(id);
}
``

- **熔断的统计窗口**：Sentinel 用滑动窗口统计请求数据（失败率、慢调用比例）。窗口大小和步长可以配置，比如窗口大小10秒、步长2秒，就是5个桶，每个桶统计2秒内的数据。
- **生产配置建议**：核心服务熔断阈值设低（快速保护），非核心服务阈值设高（容忍更多异常）。冷却时间不要太短（避免频繁熔断恢复震荡），也不要太长（影响恢复速度）。
