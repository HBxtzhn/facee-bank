## 追问 1：Eureka 的注册表是怎么存储的？

在内存里，用一个 ConcurrentHashMap 存储。外层 key 是应用名（大写），内层 key 是实例ID（格式：hostname:appName:port），value 是 Lease<InstanceInfo> 对象，包含实例信息和租约信息（注册时间、最后心跳时间、租约过期时间）。

## 追问 2：Eureka 集群是怎么同步数据的？

每个 Eureka Server 节点在收到客户端的注册/注销请求后，处理完本地逻辑，会通过 HTTP 调用把这个变更转发给集群中的其他节点。这个转发是异步的，所以节点之间会有短暂的数据不一致。客户端连接到哪个 Server 节点都可以，拿到数据可能有几十秒的延迟。

## 追问 3：Eureka 为什么选择 AP 而不是 CP？

微服务注册发现场景下，可用性比一致性更重要。如果用 CP 模型（比如 Zookeeper），当 Leader 选举期间（网络分区时），整个注册中心不可用，所有服务都无法注册和发现，新服务上不了线，老服务调用也可能受影响。AP 模型下，即使部分节点挂了，其他节点仍然可以提供服务，虽然数据可能不是最新的，但服务不会中断。
