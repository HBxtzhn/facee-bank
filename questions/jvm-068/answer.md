一个Java对象在堆内存中的存储布局分为三部分：**对象头、实例数据、对齐填充**。

## 1. 对象头（Header）

对象头占两个机器字（64位JVM默认12字节，开启指针压缩后），分为两部分：

**Mark Word（标记字段）：**

- 存储对象自身的运行时数据

- 包括：哈希码、GC分代年龄、锁状态标志、偏向线程ID、偏向时间戳等

- 64位JVM占8字节，32位占4字节

- 锁升级的时候信息存在这里：无锁 → 偏向锁 → 轻量级锁 → 重量级锁

**Klass Pointer（类型指针）：**

- 指向对象所属类的元数据（Class对象）的指针

- JVM通过这个指针知道对象是哪个类的实例

- 64位JVM开启指针压缩占4字节，不压缩占8字节

**数组对象额外多一个：数组长度**

- 数组对象的对象头里还有4字节存数组长度

- 因为数组类型相同但长度不同，需要单独记录

## 2. 实例数据（Instance Data）

- 对象真正存储成员变量的地方

- 包括本类定义的和父类继承下来的所有字段

- 存储顺序受JVM分配策略影响，一般相同宽度的字段放一起

- 顺序大致：long/double → int/float → short/char → byte/boolean → 引用类型

- 父类的字段在前，子类的在后

## 3. 对齐填充（Padding）

- HotSpot要求对象起始地址必须是8字节的整数倍

- 对象头+实例数据加起来不是8的倍数时，用对齐填充补到8的倍数

- 不是必须的，只是为了内存对齐，提升访问效率

- 对齐填充不存任何有效数据

## 示例：一个普通对象的大小（64位JVM \+ 指针压缩）

```
空对象（没有成员变量）：
对象头：12字节（Mark Word 8 + Klass Pointer 4）
实例数据：0字节
对齐填充：4字节（凑到16字节，8的倍数）
合计：16字节

一个int字段的对象：
对象头：12字节
实例数据：4字节（int）
对齐填充：0字节（刚好16字节）
合计：16字节
```

## 扩展：指针压缩（Compressed Oops）

- 64位JVM默认开启`-XX:+UseCompressedOops`

- 把64位的对象指针压缩成32位

- 堆在32G以内时，通过基址+偏移的方式用32位表示地址

- 节省内存，同时也提升缓存命中率

- 堆超过32G时指针压缩失效，回到64位指针
