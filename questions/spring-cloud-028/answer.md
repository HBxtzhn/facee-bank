1. **轮询（Round Robin）**：按顺序依次分配请求，A→B→C→A→B→C。最简单，适合所有服务器性能相同的场景。

2. **加权轮询（Weighted Round Robin）**：给每台服务器设置权重，性能好的权重大，分配更多请求。A(权重3)→A→A→B(权重1)→A→A→A→B。

3. **随机（Random）**：随机选一台服务器。请求量大时效果接近轮询。

4. **加权随机（Weighted Random）**：跟加权轮询类似，权重大的被选中的概率更高。

5. **最少连接（Least Connections）**：把请求分配给当前连接数最少的服务器。适合长连接场景（比如 WebSocket）。

6. **IP 哈希（IP Hash）**：根据客户端 IP 的 hash 值选择服务器，同一个 IP 总是分到同一台服务器。实现会话保持（Session Sticky）。

7. **一致性哈希（Consistent Hashing）**：把服务器和请求映射到一个哈希环上，请求分配给顺时针方向最近的服务器。增减服务器时只影响一小部分请求，适合缓存场景。

## 概念对比

| 算法 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| 轮询 | 按顺序轮流 | 简单均匀 | 不考虑服务器性能 | 服务器性能相同 |
| 加权轮询 | 按权重比例轮流 | 考虑性能差异 | 需要手动设置权重 | 服务器性能不同 |
| 随机 | 随机选择 | 简单 | 可能不均匀 | 请求量大时 |
| 最少连接 | 选连接最少的 | 动态均衡 | 需要维护连接数 | 长连接场景 |
| IP Hash | 按IP哈希 | 会话保持 | 服务器变化影响大 | 需要Session保持 |
| 一致性哈希 | 哈希环映射 | 增减节点影响小 | 实现复杂 | 缓存、分布式存储 |

## 扩展知识

- **Spring Cloud LoadBalancer 默认算法**：默认是轮询（RoundRobin），可以通过配置切换为随机（Random）或自定义算法。
- **Nginx 的负载均衡算法**：开源版支持轮询、加权轮询、IP hash、least_conn；商业版（Nginx Plus）还支持 fair（按响应时间分配）、universal hash 等。
- **Sentinel 的负载均衡**：Sentinel 也支持负载均衡，可以结合熔断降级一起使用，选择健康的实例调用。
