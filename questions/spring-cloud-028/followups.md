## 追问 1：一致性哈希的原理是什么？

把整个哈希值空间组织成一个虚拟的环（0 到 2^32-1），把每台服务器用 hash 映射到环上的某个位置，每个请求也用 hash 计算一个值，顺时针找到最近的服务器就是目标服务器。当增加一台服务器时，只影响哈希环上相邻的一小段请求；删除一台服务器时，也只影响它负责的那段请求。相比普通 hash（取模），增减服务器时影响范围小得多。

## 追问 2：实际项目的负载均衡用的什么算法？

内部微服务调用用的是 Spring Cloud LoadBalancer 的默认轮询算法，因为服务实例都是同构的（相同配置）。对于有状态的服务（比如需要会话保持），用 IP Hash。Nginx 对外用加权轮询，根据后端服务器的性能设置不同的权重。

## 追问 3：加权轮询的权重怎么确定？

根据服务器的配置（CPU、内存）和压测结果来确定。比如 8核16G 的服务器权重设为3，4核8G 的设为1。也可以通过压测找到每台服务器的最佳 QPS，按 QPS 比例设置权重。生产环境可以通过 Nacos 的元数据动态调整权重，不用重启服务。
