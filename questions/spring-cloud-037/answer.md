1. **定义**：服务雪崩是指微服务架构下，一个服务不可用导致调用它的上游服务也不可用，故障像多米诺骨牌一样逐级扩散，最终导致整个系统崩溃的现象。

2. **产生原因**：
   - 下游服务响应变慢或不可用
   - 上游服务持续等待或重试，线程池被占满
   - 上游服务不可用，导致更上游的服务也不可用
   - 故障逐级扩散，最终整个系统崩溃

3. **典型场景**：服务 A 调用服务 B，服务 B 调用服务 C。服务 C 挂了 → 服务 B 的线程被阻塞等待 C 的响应 → 服务 B 的线程池被占满 → 服务 B 也挂了 → 服务 A 调用 B 也超时 → 服务 A 也挂了。

4. **预防措施**：
   - **超时控制**：设置合理的超时时间，不要无限等待。
   - **熔断器**：失败率超过阈值自动熔断，快速失败。
   - **限流**：限制入口流量，防止系统过载。
   - **降级**：服务不可用时返回兜底数据。
   - **线程隔离**：不同服务用不同的线程池，防止故障扩散。

## 扩展知识

- **雪崩的三个阶段**：初始故障（某个服务挂了）→ 资源耗尽（调用方的线程池/连接池被占满）→ 故障扩散（调用方也挂了，继续向上游扩散）。
- **重试风暴**：如果上游服务配置了重试策略，下游服务挂了会导致大量重试请求，进一步加重下游服务的负担，加速雪崩。
- **生产案例**：2017年 AWS S3 故障导致大半个互联网受影响，就是典型的服务雪崩——一个配置变更导致 S3 的一个区域不可用，依赖 S3 的服务全部受影响。
