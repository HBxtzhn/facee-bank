- **跳表（Skip List）** 是一种基于有序链表的数据结构，通过多层索引实现 O(log N) 的查找、插入、删除。
- **结构**：底层是完整的有序链表，上层逐级抽取部分节点作为索引层。查找时从最高层开始，向右或向下移动，类似二分查找。
- **Redis 中跳表的应用**：ZSet 的底层实现之一（当元素数量 > 64 或任一元素长度 > 64 字节时使用）。
- **随机层数**：新节点的层数通过随机算法生成（概率 p=0.25），最高 32 层（`ZSKIPLIST_MAXLEVEL`）。期望层数为 `1/(1-p) = 1.33`。

## 扩展知识

- **跳表 vs 平衡树**：跳表实现简单，范围查找更方便（直接遍历底层链表）；平衡树（如红黑树）需要复杂的旋转操作。跳表的平均时间复杂度与平衡树相当，但常数因子略大。
- **Redis 跳表的特点**：
  - 每个节点包含 `backward` 指针，支持反向遍历。
  - 每个节点包含 `span` 字段，记录到下一个节点的跨度，用于快速计算 rank。
  - 节点按 score 排序，score 相同时按 member 字典序排序。
- **查找过程**：从 header 的最高层开始，若当前节点的下一个节点 score < target，则向右移动；否则向下移动一层。直到第 0 层找到目标节点。

## 对比表格

| 特性 | 跳表 | 红黑树 | B+ 树 |
|------|------|--------|-------|
| 查找复杂度 | O(log N) | O(log N) | O(log N) |
| 插入/删除 | O(log N) | O(log N) + 旋转 | O(log N) + 分裂/合并 |
| 范围查找 | 高效（底层链表） | 需中序遍历 | 高效（叶子链表） |
| 实现复杂度 | 简单 | 复杂（旋转平衡） | 中等 |
| 内存开销 | 每节点多层指针 | 每节点 1 个颜色 + 2 指针 | 节点存多个 key |
| 缓存友好性 | 较差（链表） | 较差（树节点分散） | 好（节点紧凑） |
